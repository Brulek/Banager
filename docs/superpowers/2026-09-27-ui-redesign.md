# Banager 界面重构方向（2026-09-27）

作者的要求：界面与操作便捷程度太差；参考 CleanMyMac 的界面与 360 软件管家的操作逻辑；站在用户视角重构；
界面上不要有那么多 AI 思考的痕迹。

## 诊断（改之前的样子）

- 中文文案 267 条，超过 60 字的 48 条、超过 100 字的 24 条，而且**直接铺在列表行和横幅里**：推理过程（"Banager
  没有安全的办法替你做这件事"）、含糊措辞（"多半""也可能只是碰巧同名的另一个程序"）、括号里的补充说明、
  PATH / pin / 实例 / 来源这类内部词。用户扫一眼列表，读到的是一段段解释，而不是"有什么、能做什么"。
- 没有首页：一打开就是列表，看不出"我的 Mac 现在怎么样"。
- 没有常驻的"重新检查"。
- 不能点的行（固定、只读、查不了、会自己更新）和能点的行长得差不多，靠一大段话区分。

## 原则

1. **一屏一件事，默认只给结论。** 每一行只说：它是什么、现在什么版本、能做什么。为什么不能做，用一个短标签
   （「已固定」「仅供查看」「自动更新」「无法检查」）表达；想知道细节再点开。
2. **细节按需出现。** 解释收进行详情抽屉或 ⓘ 气泡，最多两句；命令行（argv）只在「显示技术细节」打开时出现。
3. **文案规则（去 AI 痕迹）**：按钮 ≤ 6 个字、动词开头；行内说明一行以内；不写推理过程、不写"多半/可能/也可能"，
   不写括号补充，不出现 PATH、pin、实例、来源 这类词（用「Homebrew」「命令行」「固定版本」这样的用户词）；
   出错时说发生了什么、怎么办，一句话。**短了也必须是真话**——宁可少说，不说错。
4. **360 的操作逻辑**：更新页顶部是「N 个可更新」+「全部更新」；每行一个「更新」按钮；次要操作
   （跳过这个版本、不再提醒、拷贝命令）收进行尾「⋯」菜单；点了更新，**进度就在这一行里**，完成后打勾；
   卸载页（已安装）按来源筛选、可搜索、可按名字排序，每行一个「卸载」。
5. **CleanMyMac 的界面感**：左侧深色侧栏（每个功能一个图标 + 计数角标），右侧大留白；首页是"一眼看清 + 一个大按钮"；
   结果页有汇总和一个主操作；动效只用在"点了之后发生了什么"（行内进度、完成打勾），不做装饰性动画。

## 视觉

- 字体：系统字体（macOS 上是 SF Pro / 苹方），这是一个原生 Mac 工具，跟系统一致是有意的选择。
- （2026-09-29 起由 `2026-09-29-aesthetics-spec.md` 取代：系统侧栏、系统灰、跟随系统的强调色。）
- 颜色：侧栏深色（接近 macOS 深色侧栏的 slate），内容区浅色；一个主色做主按钮与进度；每个来源一个识别色，
  只用在小图标底色上（Homebrew 琥珀、npm 红、Python 蓝、Rust 铁锈、Ollama 黑、Claude Code 陶土、Grok 黑、Antigravity 蓝紫）。
- 深色模式跟随系统。圆角有层级：窗口面板大、行小、标签胶囊。
- 不做：渐变装饰、每张卡片同样的阴影、全大写小标签、`A · B · C` 堆砌、链接后面加 →。

## 分步

1. 浏览器预览模式（开发用，不进正式版），先把现状截图。
2. 设计基础：配色与间距变量、侧栏、页头（含「重新检查」与上次检查时间）。
3. 概览首页（新）。
4. 更新页：行结构、⋯ 菜单、行内进度、全部更新。
5. 已安装页：筛选、搜索、行结构、依赖折叠。
6. 文案重写：en + zh-CN 全部过一遍，长解释移进详情抽屉 / ⓘ 气泡。
7. 对话框（卸载、更新确认）、操作条、日志抽屉、来源不明页、设置页。
8. 截图走查 + 测试 + 复审：每一步都截图对照，测试跟着改（测试断言的是行为，不为了过而放宽）。
